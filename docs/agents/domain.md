# Domain Docs

## Antes de explorar uma área

Leia `GLOSSARY.md` na raiz, se existir, e os documentos de `docs/adr/` relevantes para a área.

Se existir `GLOSSARY-MAP.md`, siga seus apontamentos para os glossários pertinentes. Na ausência desses documentos, prossiga; glossário e ADRs são criados quando termos ou decisões forem efetivamente resolvidos.

## Estrutura adotada

O projeto usa single-context: um `GLOSSARY.md` e um diretório `docs/adr/` na raiz.

## Vocabulário e decisões

Use os termos do glossário em código, testes, tickets e explicações. Uma lacuna de terminologia deve ser resolvida com a skill `domain-modeling` quando afetar a compreensão do domínio.

Se uma proposta contrariar um ADR existente, identifique a decisão e explique o conflito antes de alterá-la.
